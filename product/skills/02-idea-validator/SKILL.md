# Скилл · Валидация собственной идеи/проекта команды (роль: команда)

## Задача
Команда пришла не с задачей из базы, а со своей идеей («мы вот что придумали») или уже существующим проектом («у нас есть вот такой проект») любой степени готовности. Проверь материал по тем же критериям, что и генерацию задач, и выдай рекомендательный отчёт.

## Вход
- Описание идеи/проекта от команды в свободной форме (чем полнее, тем глубже проверка).
- Пакет контекста `workspace/0-context/` — если доступен; если нет, критерии 1 и 2 проверяются условно с пометкой «нужен контекст».

## Критерии (те же, что в Шаге 1)
1. Связь с гос. приоритетами (по рамке из контекста).
2. Соответствие научно-техническому заделу и компетенциям вуза.
3. Реализуемость-коридор: достижимо приращение готовности (мин. +1 TRL/MRL) за срок акселерации силами команды; не многолетний НИОКР сверху, не рутина без технологического содержания снизу.
4. Рыночный потенциал без vendor-lock: решение обобщаемо на сегмент, а не привязано к одному заказчику.
5. Образовательный потенциал: команда учится на проекте основам технологического предпринимательства.

## Процедура
1. Глубина проверки сообразна готовности входа: для сырой идеи — оценка замысла; для готового проекта — оценка соответствия рамке и коридора развития.
2. По каждому критерию — вердикт (соответствует / условно / не соответствует) + обоснование + что усилить.
3. В конце: список из 3–5 конкретных шагов, как поднять валидность слабых критериев.

## Выход
- Отчёт валидации в `workspace/2-teams/<имя>/`.

## Важно
- Вердикт рекомендательный: низкая валидность — не блокер, а пространство для решения команды и организатора.
- Не переписывай идею команды; максимум — показываешь, куда её усиливать.
