# Скилл · Шаг 1 — генерация проектных задач (роль: организатор)

## Задача
Сгенерировать базу проектных задач в рамке четырёх основ из `workspace/0-context/` и прогнать каждую через внутренний валидатор. Итог — перечень задач в требуемом организатором числе.

## Вход
- Пакет контекста `workspace/0-context/` (заявка, паспорт АП, рамка приоритетов, реестр партнёров, НТЗ вуза).
- Число задач: по умолчанию число команд АП + 15% (округлить вверх); генерируй с этим запасом.

## Рамка специализации — фильтр до валидации
1. Сегмент/тематическое направление каждой задачи — только из перечня, прямо указанного в паспорте АП (тематические направления, сегменты рынка, стыки рынков). Расширять сегментацию по своему усмотрению запрещено: дип-ресерч дополняет нормативную рамку приоритетов, но не тематическую специализацию заказчика.
2. Сквозные технологии (например «ИИ в отраслях экономики») — признак способа решения, а не сегмента: одного их соответствия недостаточно для отнесения задачи к специализации АП.
3. В полях «связь с приоритетом» и в валидации запрещено ссылаться на блоки рамки, которых в ней нет (несуществующие критические технологии, НПТЛ и т.п.).
4. Задача вне перечня сегментов паспорта АП — вне специализации: по 5 критериям не валидируется, а перегенерируется или отбрасывается.

## Пять рамочных критериев (проверяется каждая задача)
1. **Гос. приоритеты** — задача лежит в поле приоритетов из рамки (со ссылкой на конкретное место рамки).
2. **Компетенции вуза** — лежит в поле научно-технического задела и направлений подготовки вуза.
3. **Реализуемость (коридор)**: за срок акселерации силами студенческой команды с инфраструктурой вуза достижимо измеримое приращение готовности (минимум +1 уровень TRL/MRL). Сверху: задача не требует многолетнего НИОКР; если MVP за срок недостижим — требуется достижимый промежуточный результат (например, переход от анализа к экспериментальной проработке). Снизу: задача не сводится к типовой инженерной рутине без технологического содержания. Ресурсно: нужны команда + инфраструктура вуза + наставник.
4. **Рынок без vendor-lock**: индустриальный партнёр — первый покупатель/пилотный пользователь, но решение обобщаемо на сегмент рынка (проверяется именно обобщаемость). Задачи, порождённые заделом вуза (НТЗ) без партнёра-заказчика: потребителя не фабрикуй — явно пометь «первый покупатель не определён (задача из НТЗ вуза)» и ставь критерию «условно»; судьбу задачи решает организатор на валидации. Партнёра называй первым покупателем только если задача происходит из его запроса (реестр/таблица задач паспорта АП); иначе указывай его как «кандидат в покупатели (запрос партнёра не подтверждён)» — не приписывай партнёру несделанного заказа.
5. **Образовательный потенциал** — команда учится на задаче основам технологического предпринимательства согласно критериям из паспорта АП.

## Процедура
1. Каждую задачу оформи по `templates/01-project-task-passport.md` — отдельным файлом в `workspace/1-tasks/`.
2. Валидация обязательна: по каждому из 5 критериев — вердикт (соответствует / условно / не соответствует) с обоснованием и ссылкой на место в контексте. Валидация хранится вместе с задачей. Итог задачи — одна из трёх градаций: **высокое** (все пять — «соответствует»), **проходное** (не более одного «условно», остальные — «соответствует»), **в резерв** (два и более «условно» либо хотя бы одно «не соответствует»). Единый вердикт на весь портфель («все проходные») — брак валидации: он лишает отбор смысла.
3. Задачи градации «в резерв» перегенерируй. Лимит — 2 цикла валидации. После лимита портфель собирается из «высоких» и «проходных»; если их меньше требуемого числа — не добирай из резерва и не снижай порог: сообщи организатору фактическое число задач, состав резерва и диагноз пула.
4. Пограничные сочетания отсекай без жалости: высокая актуальность при нулевой образовательной ценности — в отброс (акселератор — часть обучения студентов).
5. Формулировка задачи — открытый вызов: понятный объект и критерий успеха, без заранее навязанного решения.

## Выход
- Перечень задач в `workspace/1-tasks/` + сводка портфеля `workspace/1-tasks/00-сводка-портфеля.md` — обязательный артефакт, без него Шаг 1 не закрыт: распределение только по сегментам паспорта АП (без собственных сегментов), группировка по материнским концепциям (смысловым семействам задач, из которых выросло несколько задач — для ярмарки и портфельного баланса), критерии отбора из исходного пула (сколько было, по каким правилам отобрано), счётчик градаций (высокое / проходное / в резерв) и состав резерва.
- Дальше — валидация задач организатором (вне агента), затем ярмарка и работа команд.

## Границы
- Не придумывай партнёров и задел: задача может опираться только на то, что есть в пакете контекста.
- Не вставляй финмодели и детальные планы.
