# Процедура глубокого поиска для Шага 0

Отчуждаемая процедура. Поисковый слой настраиваемый: основной механизм — Yandex Search API (ключ организатора); без ключа — агент выдаёт план поиска и список запросов, а сбор источников делает человек.

## Поисковый слой

**ПРИОРИТЕТ КАНАЛОВ, менять нельзя:** 1) Yandex Search API по рецепту (проверочный вызов ключа до сбора); 2) если ключ не задан/не работает — резервный режим (веер запросов человеку), НЕ другой поисковик. Другие поисковые каналы (Exa, Serper, нативный поиск среды, любые Google-based MCP) — только дополнительный канал поверх Yandex, и подменять ими основной механизм ЗАПРЕЩЕНО: Google-подобные индексы дают системные дыры на российском нормативном слое (гос. сайты лочат их краулеры) — поиск выглядит работающим, а карта собирается с пробелами без всяких сигналов.

**Основной механизм — прямой вызов Yandex Search API v2** по рецепту `yandex-search-recept.py` (лежит рядом с этой инструкцией, instructions/) (эндпоинт `searchapi.api.cloud.yandex.net/v2/web/search`; ключ и folder_id — только через переменные окружения `YANDEX_SEARCH_API_KEY` / `YANDEX_FOLDER_ID`; тело строго UTF-8 через python; ответ — base64 XML; пауза ~10 с между вызовами; searchType SEARCH_TYPE_RU).

Почему основной механизм именно такой:

- **Гос. сайты и правовые базы лочат Google-краулер по IP** — поиск через Google (Serper и аналоги) «работает, но молча собирает дыры»: карта получается неполной без всяких сигналов. Это системное искажение, а не случайный сбой.
- **Нативный веб-поиск среды зависит от модели/провайдера** — непереносим и не годится как контракт.
- Российская поисковая инфраструктура блокировок не имеет и закрывает российский нормативный слой (приказы-методики, сводники Росстата, карточки ЕПБС).

Правила слоя:

1. **Проверочный вызов перед сбором**: один тривиальный вызов API. Ключ не задан/не работает — не начинать сбор: сообщи организатору, что поиск недоступен, и переходи в резервный режим (ниже). Не жги бюджет поисков на неработающем канале.
2. **MCP yandex-search — опция среды, не контракт**: если в среде есть именно он — можно использовать вместо рецепта; отсутствие MCP не блокирует (рецепт работает в любом окружении с python и исходящим HTTPS). Другие поисковые MCP (Exa, Serper и т.п.) — не замена основному механизму (см. приоритет каналов выше).
3. **Нативный веб-поиск среды — опциональный дополнительный канал** (например, международный/ненормативный контекст, где у Яндекса нет преимуществ). Не основной, не проверяемый гейт; результаты его — через ту же проверку источников.
4. **Бюджет — квотами по каналам**, не сквозным счётчиком: распредели бюджет поисково-открытий по каналам В1–В7 и веерам заранее (ориентир: 20–25 поисково-открытий на полный веер — распределяй с запасом). Недобор канала — честный пробел, добор отдельным прогоном.
5. Ключ получает организатор вуза (аккаунт Yandex Cloud → подключить Search API → API-ключ + folder_id). Инструкция по получению ключа — в шапке рецепта.

## Принцип веера запросов

Не один запрос, а веер из 4–5 векторов, в каждом — 3–5 вариаций запросов:

1. **Нормативная база**: действующие документы уровня страны и отрасли по направлению (национальные цели, стратегии, перечни технологий).
2. **Приоритеты и программы**: нацпроекты технологического лидерства и их паспорта, федеральные проекты, программы профильных ведомств. Обязательно получить **перечень действующих НПТЛ** (с 2025 г. — девять проектов; перечень и описания: национальныепроекты.рф, нтр.рф) и отобрать релевантные направлению — «два-три угаданных нацпроекта» не считаются рамкой. Важная норма: паспорта НПТЛ нового цикла утверждаются **протоколами президиума Совета при Президенте РФ по стратегическому развитию и национальным проектам** (для девятки цикла 2025–2030 — протокол от 20.12.2024 № 12пр), которые официально не публикуются: полный текст паспорта НПТЛ в правовых базах (КонсультантПлюс, Гарант, legalacts) искать не нужно — его там нет, и это не сбой поиска. Реквизит рамки фиксируется по цитатам в открытых приказах ведомств о методиках показателей; содержательный уровень — паспорта федеральных проектов (публикуются выборочно) и отраслевые документы (см. «Барьерный слой»).
3. **Отрасль и рынок**: задачи, барьеры, точки роста отрасли; отраслевые стратегии и дорожные карты.
4. **Ландшафт решений**: государственные информационные системы и реестры российской продукции — что уже существует.
5. **Индустриальные запросы**: открытые запросы корпораций на инновации, закупки НИОКР, инновационные программы компаний.

Веер формируется от технологического направления АП (из заявки организатора); сегмент сужается до конкретной части цепочки, «весь рынок» — не сегмент.

## Стартовые подсказки задания — только разведка

Реквизиты, переданные в задании (номера приказов, даты, привязки к нацпроектам) — **стартовые подсказки** (сиды, в терминологии агентных сред) — подлежат той же проверке, что и найденное: **подсказка может указывать на чужой объект** (чужой нацпроект, отменённый акт, опечатка в номере).

- Стартовая подсказка — гипотеза для первого запроса, не опора: сначала верификация реквизита по независимому зеркалу (pravo.ppt.ru, rulaws.ru, legalacts.ru), потом использование.
- Доверенный источник перечня методик показателей — сводники Росстата по федпроектам (`rosstat.gov.ru/storage/mediabank/FP0*_N.htm`) и реестр методик на сайте Росстата, а не память или стартовые подсказки задания.
- Неподтвердившаяся подсказка в карту не вносится; в протоколе — пометка «подсказка не подтвердилась, что нашлось вместо».

**Разграничение «вход заказчика vs материалы агента»**: документы, лежащие рядом с загруженными, — не обязательно вход заказчика. Файл-референс («для примера», «учебный», архив прошлых исследований) — справочник формата: его содержимое не становится источником задач, а его владелец — покупателем. Вход — только предъявленные заказчиком документы (минимум — паспорт АП); статус спорного документа выясняй у организатора до добора, иначе считай референсом. Основы, собранные агентом, помечай «сгенерировано агентом на Шаге 0» (правило продублировано в 00-intake).

## Веер по индустриальным партнёрам (если запросов нет)

Если реестр партнёров предъявлен без структурированных запросов — для каждого партнёра ведётся мини-веер:

1. **Официальный сайт**: продукты, специализация, клиентские сегменты, инновационные программы.
2. **Публичные запросы на инновации**: разделы «инновации»/«стартап-программы» на сайте, конкурсные площадки.
3. **Закупки НИОКР**: ГИС «Электронный бюджет», закупочные площадки (по наименованию партнёра).
4. **Индустриальный контекст**: новости, пресс-релизы о цифровизации/технологиях партнёра.

Результат заполняет реестр партнёров (`templates/05-partner-requests-registry.md`) — по каждому пункту источник. Это основа основы «запросы индустриальных партнёров» и главный сырьевой пул Шага 1: идеи, выросшие из реального бизнеса партнёра, кратно сильнее идей «по профилю».

## Иерархия источников (чему доверять в первую очередь)

1. Официальные нормативные и стратегические документы.
2. Паспорта нацпроектов технологического лидерства и документы профильных ведомств.
3. Отраслевые стратегии, реестры, государственные информационные системы.
4. Запросы индустриальных партнёров, корпоративные программы, закупки НИОКР.
5. Аналитика, форсайты, материалы ассоциаций и институтов развития.

Правила:

- **Правило двух опор**: барьер/задача подтверждается минимум одним официальным источником (рамка: почему важно) и одним индустриальным источником (подтверждение: проблема существует здесь и сейчас).
- Отсутствие решения в реестре — не доказательство барьера; реестр показывает ландшафт.
- Аналитика (уровень 5) уточняет контекст, но не может быть единственным подтверждением приоритета.

## Проверка каждого источника (обязательно)

Статус (действует/заменён/отменён) · Дата публикации/обновления · Редакция (последняя ли) · Уровень (какой строке иерархии соответствует) · Применимость (к теме, а не «отрасли вообще») · Подтверждение (есть ли независимый источник под вывод).

## Барьерный слой: каналы добычи технологических барьеров

Паспорт НПТЛ — агрегатная рамка: барьеров в нём нет и в открытом доступе он не публикуется. Барьеры добываются ниже по лестнице, из открытых каналов — в порядке убывания силы (эшелон: ✅ программно / ◐ фрагментарно / ⚠ браузер или человек):

| # | Канал | Что даёт для барьера | Эшелон |
|---|---|---|---|
| В1 | Приказы ФОИВ о методиках расчёта показателей НПТЛ (legalacts, КонсультантПлюс) | Формулы «уровня технологической независимости отрасли» — официальные определения, что считается барьером и по какому параметру | ✅ |
| В2 | Выгрузки ЕПБС / открытые данные бюджета (DataBudget) | Значения показателей «база-2024 → цель-2030»: **разрыв показателя — барьер-кандидат в измеримой форме** | ✅ |
| В3 | Паспорта федеральных проектов в составе НПТЛ (поиск по названию ФП) | Мероприятия, задачный уровень; публикуются выборочно | ◐ |
| В4 | КНТП и перечни критической продукции (распоряжения Правительства, перечни Минпромторга) | Конкретные критические технологии и номенклатура направления | ◐ |
| В5 | Отраслевые стратегии и планы ведомств-кураторов | Отраслевые задачи, узкие места с цифрами | ✅/◐ по ведомству |
| В6 | Дорожные карты НТИ (nti2035.ru) | Технологические разрывы рынков — с обязательной проверкой даты (правило актуальности) | ✅ |
| В7 | ГИСП, реестры российской промышленной продукции | Технологический ландшафт: что уже существует. Ландшафт — не доказательство барьера | ⚠ браузер |

**Правило показателя**: «показатель + методика расчёта + разрыв между базой и целью» = барьер-кандидат с параметром и официальной опорой — даже без доступа к паспорту НПТЛ.

**Верификация формул и чисел:**

- Формулы в приказах набраны **изображениями** — текстовый слой их не видит. Восстановление: по дословным описаниям символов на правовых зеркалах + сверка с PDF методик Росстата (`rosstat.gov.ru/storage/mediabank/MET_N_*.pdf`, скачиваются `curl -k`, читаются pypdf) и вторым зеркалом. Восстановленная формула вносится с пометкой «восстановлена по описанию, сверить со сканом».
- Числа «база-2024 → цель-2030» и годовые траектории ищи в **ЕПБС/DataBudget** (`databudget.ru/projects/np/<код>`, `/fp/<код>`) — открыто и верифицируемо. При расхождении ЕПБС и паспорта ФП приоритет у ЕПБС (действующая учётная система, моложе); паспортные значения сохраняй как прежнюю траекторию с пометкой.
- Каталог методик одного ФП — сводник Росстата `FP0*_N.htm`: одна страница с перечнем всех приказов-методик; искать приказы по одному дороже.

**Карта доступности площадок (РФ-сегмент; перед использованием перепроверить точечно — сайты меняют доступность):**

- ✅ программно: databudget.ru (ЕПБС-карточки), сводники и PDF методик Росстата (curl -k), legalacts.ru, pravo.ppt.ru, rulaws.ru, sudact.ru, национальныепроекты.рф (PDF паспортов — octet-stream, читать pypdf), minobrnauki.gov.ru.
- ◐ фрагментарно: КонсультантПлюс — полные тексты только рабочими днями 20:00–24:00 МСК («ночной эшелон»); zakupki.gov.ru/ЕИС — connect timeout программно (закупки — через агрегаторы или браузер); docs.cntd.ru — нестабильно.
- ⚠ браузер/человек: gisp.gov.ru, нтр.рф (403 программно), government.ru (стоп-лист — брать с зеркал: crp.gov.ru, национальныепроекты.рф), rostec.ru (self-signed cert), fedstat.ru/ЕМИСС (не проверено — проверить точечно).
- IFR «World Robotics» — платный; карта технологической кооперации нацпроекта — не публикуется (это норма, не сбой).

**Сборка барьера** (строка карты барьеров шаблона 04): критическая технология или показатель → разрыв с параметром (канал В1–В6, ссылка) → кто страдает/платит сейчас (индустриальная опора: запрос партнёра, закупка НИОКР, программа корпорации). Сошлись две опоры — барьер подтверждён; только официальная — барьер-гипотеза, попадает в карту с пометкой «требует индустриального подтверждения».

**Индустриальные опоры:** прямые закупки программно закрыты — собирай опоры из мер поддержки (ГИСП-навигатор — браузерный эшелон), корпоративных программ (через открытые вторичные публикации), отраслевых ассоциаций и их журналов, аналитики с датами. Косвенная опора (оценка дефицита без запроса/закупки) не конфирмирует барьер — оставляй гипотезой.

**Резервная лестница**: если по направлению связка «криттехнология → барьер» из каналов В1–В7 не собралась (проект новейший, слой беден) — веер обычного веб-поиска без ограничения уровня источника, но с полной проверкой статус/дата/редакция и явной пометкой «опора ниже уровня 3 иерархии»; конечный резерв — человек по вееру запросов (браузерный эшелон: витрины government.ru, PDF-паспорта на нтр.рф, профильных ресурсах ведомств).

## Резервный режим: поиск недоступен, ключ не задан или нестабилен

Среда может не иметь ключа Yandex API, исполняемого python, либо выдавать заглушки, зависания и обрывы. Правила:

1. Проверочный вызов ключа (см. «Поисковый слой») не прошёл — не начинать сбор программно: сразу переходи в резервный режим и сообщи организатору, что нужно (задать ключ по инструкции рецепта) либо собрать вручную.
2. Не блокируй шаг и не жди бесконечно: несколько повторов без результата — переходи к резервный режим (в т.ч. с фоновым субагентом: если он завис — сними задачу, сохранив собранное).
3. В резервный режиме агент выдаёт **веер запросов и план ручного сбора** (по каналам В1–В7 с адресами площадок из карты доступности), а сбор делает человек: открывает площадки, сохраняет находки в папку контекста. *(TODO: отчуждаемая человекочитаемая инструкция ручного сбора — отдельным документом; пока план сборки даёт агент по этой процедуре.)*
4. Сохрани всё найденное и веер запросов отдельным артефактом-приложением к недостроенной основе (например `04a-рамка-глубокого-поиска.md`): что найдено (с источниками и статусами), что недобрано, веер запросов для добора.
5. Недобранное оставайся честным пробелом в протоколе достаточности — не заполняй предположениями и не используй как подтверждение.
6. Добор — повторным глубоким поиском (после починки ключа) или человеком по вееру запросов; найденное человеком отдавай на подтверждение заказчику как обычно.
7. Правило «не блокирует Шаг 1» — точная область применения: оно допускает пропуск дип-ресерча ТОЛЬКО если (а) основы (заявка, реестр партнёров, НТЗ) предъявлены организатором хотя бы частично, (б) поиск реально недоступен (ключа нет/канал мёртв), и (в) организатор ЯВНО решил идти без добора. Нельзя: применять это правило, когда поиск доступен но не выполнен; объявлять Шаг 1 готовым к запуску при несобранных основах; решать за организатора. Перед переходом к Шагу 1 агент обязан показать статус каждой из 4 основ (предъявлена/сгенерирована/не собрана + что добрано) и получить явное подтверждение организатора «переходим к Шагу 1» — при несобранной рамке приоритетов генерация запрещена (задачи повиснут на «сырьё рамки» и опыте, а не на гос. приоритетах).
